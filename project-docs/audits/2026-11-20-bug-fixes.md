## Failures seen during review

- `RechargeUITests/testTheTrialOfferIsLegibleAtTheLargestTextSize` failed in `...-161525-14692` (code at `7f87451`). Caused by the branch: once `b456dac` made the test run at a real AX5 size, the B4 layout puts the CTA below the fold (y = 2172 in an 874 pt window), and the shared walk helper waited for it to be hittable without scrolling. Fixed in `b286f33`: the helper takes `measuringOffer: false` for that test, and the test scrolls up to 8 times before asserting the CTA is hittable. Nothing is asserted less. It passed 3 of 3 iterations in `...-171015-30694`.
- `RechargeUITests/testThePurchaseCTALandsWhereTheContinueButtonWas` failed in `...-161525-14692` and in 2 of 3 iterations of `...-171015-30694`, and passed 3 of 3 on base code (`recharge-base-review-mbpro32045-1121-180353-29816`). Not caused by the branch. Every failure was a timeout on the shared walk helper's 10 s hittable wait while the runner was stalled: in the full run, launching the app for this test took 35 s to set up the automation session and each element lookup took 15 to 20 s on the welcome page, which the branch does not touch. The test just before it walked the same flow and passed in 42 s. Iteration 3 of the rerun failed with "Failed to terminate com.jackwallner.recovery" before the test body ran. It passed at HEAD in iteration 1 of the rerun and in the final full run `...-182151-7265`. Listed as a runner-load flake, not a pre-existing product failure.

## Purchase and trial flow changes

- `Recharge/Views/TrialOfferPage.swift`: at accessibility text sizes only, the pitch and the buttons share one scroll view (B4). It also finishes once when `isPro` flips after a pending purchase, and restore uses the same once-only path (B5). Copy, offer order, prices and the default-size layout are unchanged.
- `Recharge/Views/PaywallView.swift`: also dismisses when `isPro` flips after a pending purchase (B5).
- `Shared/Services/StoreService.swift`: a thrown `paymentPendingError` returns `.pending` instead of propagating (B5). DEBUG-only `RECHARGE_DEFER_PURCHASE` hook for the UI test.
- `Recharge/Views/RootView.swift`: a Ready alert or widget tap closes the trial offer and paywall sheets unless a purchase is in flight (B11, which names `showTrialOffer`). The upgrade request from the detail card now arrives after the detail closes (B1).

No purchase-flow change goes beyond the element its bug names, and nothing was reverted.

## Worth a look on a real device

- B5: a real Ask to Buy purchase in a Family Sharing group. The test uses a simulated pending error. That RevenueCat throws `paymentPendingError` (rather than returning a cancelled or empty result) is the SDK's documented behavior, not something seen here.
- B2: a morning lift that needs an effort answer plus an evening run, answered on a real Watch, with both builds updated together. A new Watch paired with an old phone build asks generically. An old Watch with a new phone keeps the old wording bug.
- B7: the review ask and "opens before first pitch" now count only foreground opens, so existing users reach the 6-launch threshold later than before. That is intended.
- B6: after updating, a user whose last hard countdown was hidden by a walk gets that Ready moment counted once, possibly days late, which can arm the review ask on the next open.
- B9: the effort sheet closing animation, which no capture covers.
- B3: only reachable with a corrupted store; the anchor reset is unit-tested and the re-import itself was not run against real Health.
